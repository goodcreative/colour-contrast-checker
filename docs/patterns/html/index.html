Patterns

Architectural patterns used across this codebase — each one written up with the problem it solves, how it's wired in this project, and the trade-offs that come with it.

Vue 3 · Composition API Pinia Vitest

These four patterns together cover how the app stays testable, fast, and maintainable as features have been added. Hexagonal architecture isolates the store from the browser; the URL codec handles serialisation at the boundary; the two-stage computed pipeline keeps reactive work cheap where it matters; and the thin-wrapper component keeps UI duplication in check.

Each page describes the problem, shows the implementation in this codebase, and lists the advantages and disadvantages so you can judge when (and when not) to reach for the pattern.

Hexagonal Architecture

hexagonal-architecture.html
stores/ adapters/ provide/inject

Ports & adapters at the store boundary. The store calls injected UrlPort and StoragePort objects — production wires window in; tests wire plain JS objects in — without changing a line of business logic.

Two-Stage Computed Pipeline

two-stage-computed-pipeline.html
stores/ composables/ O(N²) → cached

Split expensive contrast math from cheap pass/fail bucketing into two cascading computed() calls. Toggling AA ↔ AAA invalidates only stage 2 — scoredPairs stays cached and the O(N²) loop never re-runs.

Thin-Wrapper Component

thin-wrapper-component.html
components/ Vue v-model ~10-line wrappers

One self-contained ModeToggle owns all rendering and behaviour; ComplianceModeToggle and ContrastModeToggle are paper-thin wrappers that do nothing but bind options and store state through v-model.

URL Codec

url-codec.html
composables/ pure functions validation at boundary

A pure encode/decode module that centralises URL serialisation and validates incoming params before they reach the store. Malformed values fall back to defaults rather than crash; the store assigns directly with no null guards.
